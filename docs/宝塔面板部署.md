# 生电服务器官网：宝塔面板部署指南

本文说明如何在 **Linux 服务器**上使用 **宝塔面板（BT Panel）** 部署本项目：前端（Vite 构建的静态资源）+ 后端（Node.js + Express）+ MySQL，与仓库内 `docs/DEPLOYMENT.md`（本地开发）互补。

> **说明**：宝塔面板主要面向 **CentOS / Ubuntu / Debian** 等 Linux 发行版。若你只在 Windows 本机开发，请继续参考 `docs/DEPLOYMENT.md`；线上站点通常是一台 Linux 云服务器 + 宝塔。

---

## 一、架构与端口（便于你对照面板）

| 组件 | 作用 |
|------|------|
| **MySQL** | 存储站点配置、卡片、管理员等（Prisma） |
| **Node 后端** | 监听 `PORT`（默认 **4000**），生产环境默认绑定 **`0.0.0.0`**（可用 `LISTEN_HOST` 覆盖），提供 `/api`、`/uploads`，并托管 `frontend/dist`（单页应用） |
| **Nginx（宝塔）** | 对外 **80/443**，通过**反向代理**把流量转到 `http://127.0.0.1:4000` |

生产环境下**不需要**单独用 Nginx 的「网站根目录」托管 `dist`；只要前端已构建且路径可被后端找到，**一个 Node 进程**即可同时服务页面与接口（见 `backend/src/index.ts`）。

---

## 二、服务器与宝塔准备

1. 准备一台已备案（若使用国内机房且绑定域名）的云服务器，安装 **宝塔面板**（官方：https://www.bt.cn/ ）。
2. 在宝塔 **软件商店** 中安装（版本选稳定即可）：
   - **Nginx**
   - **MySQL 8.x**
   - **PM2 管理器**（或 **Node 版本管理器** + 自行安装 PM2，见下文）

3. 在 **安全** 或云厂商安全组中放行：**80**、**443**、**22**（SSH）；**不要**对公网开放 **3306**（数据库仅本机访问即可）。

---

## 三、安装 Node.js

本项目需要较新的 **Node.js LTS**（建议 **20.x 或 22.x**）。

- **方式 A（推荐）**：宝塔 **软件商店** → 搜索 **Node 版本管理器** → 安装后，在管理界面中安装 **LTS** 版本，并记下终端里 `node -v`、`npm -v` 可用。
- **方式 B**：使用 PM2 管理器自带的 Node 环境（若版本满足要求即可）。

在 SSH 终端确认：

```bash
node -v
npm -v
```

---

## 四、创建 MySQL 数据库与用户

1. 打开宝塔 → **数据库** → **添加数据库**。
2. 数据库名示例：`sgu_server_site`，字符集选 **utf8mb4**。
3. 记录：**数据库名**、**用户名**、**密码**、**端口**（一般为 `3306`）。

> 连接串将用于后文 `DATABASE_URL`。若 Node 与 MySQL 在同一台机器，主机使用 **`127.0.0.1`** 即可。

---

## 五、上传代码

任选其一：

- **Git**：在服务器 SSH 中 `git clone` 到某目录，例如 `/www/wwwroot/sgu-server.xin`。
- **压缩包**：在本地打包上传至 `/www/wwwroot/你的目录/` 并解压（**不要**把 `node_modules` 打进压缩包，服务器上重新安装依赖）。

建议最终目录结构类似：

```text
/www/wwwroot/sgu-server.xin/
├── backend/
├── frontend/
└── docs/
```

---

## 六、配置后端环境变量

1. 在 `backend` 目录执行：`cp .env.example .env`（或手动复制），再编辑 `.env`。

2. 至少配置以下变量（值请按你的实际环境修改）：

```env
NODE_ENV=production

# 监听端口（与下文 Nginx 反代目标一致）
PORT=4000

# MySQL（示例：本机 3306）
DATABASE_URL="mysql://数据库用户:密码@127.0.0.1:3306/数据库名"

# 至少 32 位随机字符串
JWT_SECRET="请替换为足够长的随机字符串"

# 必须与浏览器地址栏完全一致（协议 + 域名 + 端口，若有）
# 示例：https://www.example.com  或  https://example.com
# 带不带 www 算两种来源，请与最终访问方式一致
FRONTEND_ORIGIN="https://你的域名"

# 可选：若前端 dist 不在默认相对路径，可显式指定（多数情况不用改）
# FRONTEND_DIST="/www/wwwroot/sgu-server.xin/frontend/dist"

# 可选：仅本机 Nginx 反代、不希望进程监听所有网卡时设为 127.0.0.1（默认生产为 0.0.0.0）
# LISTEN_HOST=127.0.0.1
```

3. **首次初始化**管理员（可选，与本地文档一致）：可在 `.env` 中设置 `SEED_ADMIN_USERNAME`、`SEED_ADMIN_PASSWORD`，仅在执行 `seed` 时使用。

## 七、安装依赖、构建与数据库初始化

在 **SSH** 中执行（路径按你实际上传位置修改）。

**方式 A（推荐）：在仓库根目录一次性安装并构建前后端**

```bash
cd /www/wwwroot/sgu-server.xin
npm run deploy:build
```

然后初始化数据库（仍在服务器上）：

```bash
cd /www/wwwroot/sgu-server.xin/backend
npx prisma db push
npm run db:seed
```

**方式 B：分目录执行**

```bash
cd /www/wwwroot/sgu-server.xin/backend
npm install
npm run build
npx prisma db push
npm run db:seed

cd /www/wwwroot/sgu-server.xin/frontend
npm install
npm run build
```

完成后应存在 `frontend/dist/index.html`，后端在生产模式下会自动检测 `../frontend/dist`（相对 **backend 进程工作目录**）并托管前端；若目录结构不同，请设置 `FRONTEND_DIST` 指向 `dist` 的绝对路径。

**自检（可选）**：临时启动一次：

```bash
cd /www/wwwroot/sgu-server.xin/backend
NODE_ENV=production npm start
```

另开终端：

```bash
curl -s http://127.0.0.1:4000/api/health
```

应返回包含 `"ok":true` 的 JSON。确认后 Ctrl+C 停止临时进程，改用 PM2 常驻运行。

---

## 八、使用 PM2 托管后端（宝塔）

1. 打开 **PM2 管理器** → **添加项目**（具体按钮名称以你面板版本为准）。
2. 关键参数建议：
   - **启动文件**：`backend/dist/index.js`（或填写 `npm`，启动参数 `start`，以你 PM2 界面支持的方式为准）。
   - **项目路径 / 运行目录**：必须是 **`backend` 目录**，例如 `/www/wwwroot/sgu-server.xin/backend`，这样 `uploads` 相对路径、`cwd` 与代码设计一致。
   - **环境变量**：可在 PM2 项目里添加 `NODE_ENV=production`，其余也可写在 `backend/.env`（`dotenv` 会加载）。

若使用命令行（与面板等价，便于排错），**推荐**使用仓库内的 PM2 配置（已固定 `cwd` 与 `NODE_ENV=production`）：

```bash
cd /www/wwwroot/sgu-server.xin/backend
npm run pm2:start
pm2 save
pm2 startup
```

也可直接：`pm2 start ecosystem.config.cjs`。

---

## 九、在宝塔中创建网站并配置反向代理

1. **网站** → **添加站点** → 填写你的域名，**PHP 版本选「纯静态」或「不部署 PHP」**即可（实际由 Node 提供动态内容）。
2. 打开该站点 → **设置** → **反向代理** → **添加反向代理**：
   - **代理名称**：任意，如 `node-api`
   - **目标 URL**：`http://127.0.0.1:4000`
   - 开启 **WebSocket**（若界面有该选项可打开；本项目以 HTTP API 为主，按需即可）
3. **保存**。此时访问 `http://域名` 应能打开站点首页（由 Node 托管的 `dist` + API 同源）。

> 若宝塔自动生成了 `location /` 之外的规则，请避免再单独把 `/api` 指到别处，保持**整站**反代到同一 Node 端口即可。

需要手写 Nginx 片段时，可参考仓库 **`deploy/nginx-reverse-proxy.example.conf`**（含 `X-Forwarded-*`，与后端 `trust proxy` 配合）。

---

## 十、HTTPS（SSL 证书）

1. 在站点 **SSL** 中申请 **Let's Encrypt** 或使用已有证书。
2. 开启 **强制 HTTPS**。
3. 将 `backend/.env` 中的 **`FRONTEND_ORIGIN`** 改为 **`https://你的域名`**（与浏览器实际访问完全一致），然后重启 PM2 进程。

---

## 十一、部署后检查清单

| 检查项 | 说明 |
|--------|------|
| 健康检查 | 浏览器或使用 `curl` 访问 `https://域名/api/health` |
| 前台首页 | 打开 `https://域名/` |
| 后台 | `https://域名/admin/login`，使用 seed 或后台创建的管理员登录 |
| 上传与图片 | Logo 等应能保存；若 403/404，检查 `backend/uploads` 目录权限与 PM2 工作目录是否为 `backend` |
| 安全 | 修改默认管理员密码；`JWT_SECRET` 保密；数据库不对公网开放 |

---

## 十二、常见问题

1. **`FRONTEND_ORIGIN` 报错或与登录/Cookie 异常**  
   必须与你的访问地址完全一致（`http`/`https`、`www`、端口）。改完后重启 PM2。

2. **页面空白或 404**  
   确认已执行 `frontend` 的 `npm run build`，且 `frontend/dist/index.html` 存在；或正确设置 `FRONTEND_DIST`。

3. **502 Bad Gateway**  
   Node 未启动或端口不是 4000；检查 `pm2 list`、`.env` 中 `PORT` 与 Nginx 反代端口是否一致。

4. **数据库连接失败**  
   核对 `DATABASE_URL`、MySQL 是否运行、用户是否有该库权限；本机连接用 `127.0.0.1`。

5. **更新版本**  
   `git pull` → 分别在 `frontend`、`backend` 执行安装与构建 → `prisma db push`（如有 schema 变更）→ 重启 PM2。
